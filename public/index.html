⚙️ 构建器设置

① 大模型接入（OpenAI 兼容，支持 DeepSeek 等）

② Cloudflare（自动发布 Worker）

🌐 在线登录（推荐，无需手动创建 Token）
类似 wrangler login：浏览器一键授权，登录态自动保存并自动刷新，无需每次登录
—— 或使用手动 API Token ——

🔒 无论哪种方式，凭据都保存在构建器自己的 KV 存储中（在线登录的令牌到期会自动刷新），部署时自动复用。 API Token 可在 dash.cloudflare.com → 头像 → My Profile → API Tokens → Create Token 创建（模板选「Edit Cloudflare Workers」）。

④ 后台执行器（解决长对话超时/中断）

🚀 对话将提交到 GitHub Actions （workflow_dispatch，单任务最长 6 小时）后台执行：LLM 生成 → 工具调用 → 部署 → 冒烟测试，结果自动写回。 仓库需包含 .github/workflows/builder-task.yml 与 agent-runner/。

🔑 PAT 获取：GitHub → 头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → 新建：Repository access 选 runner 仓库，Permissions → Actions 选 Read and write， 生成后填到此处（也可用 classic token 勾选 workflow 或 repo scope）。

🚀 对话将提交到 CNB 云原生构建 （api_trigger_builder 流水线，node:20 容器）后台执行。仓库需包含 .cnb.yml 与 agent-runner/。 CNB 容器（大陆）访问 Cloudflare 不稳定，建议填写 Clash 代理订阅：流水线会自动启动 mihomo 代理，让 构建器回调与 Cloudflare 部署走代理出口。

🔑 CNB Token：cnb.cool → 设置 → 访问令牌，勾选 repo-cnb-trigger:rw；仓库需开启「允许自动触发」。 📡 代理订阅：任意 Clash 订阅链接（yaml 或 base64），流水线内自动安装 mihomo 并启动 http://127.0.0.1:7890。

③ 访问密码（进入构建器页面时需要）
